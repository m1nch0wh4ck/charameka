# 작업지침 (AI 의미 검수용)

> 이 파일은 AI 의미 검수 때 Claude 에게 그대로 전달됩니다.
> 메모장으로 열어 자유롭게 고쳐 쓰셔도 됩니다. (rules 폴더 안의 .md / .txt 파일은 모두 전달됩니다.)

## 기계어치환 원칙
- 원본의 규칙은 **같은 강도**로 옮겨야 한다. 의미를 부드럽게 바꾸거나 해석을 덧붙이지 않는다.
- 금지 표현(X, 절대 ~하지 않는다, 금지)은 결과에서도 금지 표현이어야 한다.
  - 위반 예: "절대 반말하지 않는다" → "반말을 선호하지 않는다" / "가급적 존댓말을 쓴다"
- 필수 표현(반드시, 항상, O)은 결과에서도 필수 표현이어야 한다.
  - 위반 예: "항상 3인칭으로 말한다" → "주로 3인칭으로 말한다"
- 반대로 '가능·지향·우선·기본'을 필수·금지로 끌어올리지 않는다.
- 조건부 규칙을 무조건으로, 단일 캐릭터 규칙을 세계관·전체 인물 규칙으로 넓히지 않는다.
- 중복을 합칠 때는 각 원문의 범위·강도·조건을 모두 보존한다. 기능층이 다르면 합치지 않는다.
- 원본에 없는 설정을 만들어 넣지 않는다. (새 과거사, 새 인물, 새 능력, 새 수치 등)
- 원본의 수치·고유명사·관계는 바꾸지 않는다.
- 정서어(미련·체념·설렘 등), 존댓말·종결어미·호칭 규칙, 강도 수식어(반드시·되도록 등)는 한글로 남는다.
- 원문에 없던 약어, 대문자 메타 라벨(RELATIONSHIP_DEPTH 류), 통짜 한 덩어리 구조를 쓰지 않는다. 섹션 제목은 유지한다.

## 멜로이 플랫폼 규칙
- 등장인물 필드 5,000자 / 설명 필드 10,000자 (공백 포함)
- 프롬프트 전체 = 설명 + 등장인물 전원 + 로어북(최대 호출분 3,000자까지만 계산). 권장 20,000자 / 최대 30,000자
- 세이프티 락과 상태창 출력 지시를 넣지 않는다. 플랫폼 자체 프롬프트와 중복된다.
- 캐릭터 전용 Narration은 플랫폼 문체지침과 충돌하지 않는다. (현재형 서술 지시, 감정 이름 붙이기, 대사를 별표·괄호로 감싸기, 조연 속마음 서술 등)
- 우선순위 문장은 '플랫폼 상위 시스템 및 세이프티 설정'을 최상위에 둔다.
- 상태창(위젯) HTML 8,000자 (허용 태그 제한) / 소개 페이지 HTML 30,000자 (JS 전면 금지)

### 유저 호칭 표기
- 등장인물·설명 필드: {{user}} 사용 가능
- 변수·로어북: {{user}} X → "유저"로 표기
- 섹션 제목(# · ## · ###)에는 {{user}}를 쓰지 않는다.
- 상태창(위젯) HTML: {{user}} X → "유저"로 표기 / 소개 페이지 HTML: {{user}} 사용 가능

### 변수
- 텍스트 변수 8개 / 게이지 3개 이내
- 변수 이름에 공백 X
- 변수 내용 200자 이내
- 위치·스토리날짜·현재시각 변수는 특수 명령어 실행 턴에 바뀌지 않는다는 조건을 포함한다.
- 게이지는 하한값 기준 4단계(85 / 60 / 30 / 0 이상)로 빈 구간이 없다.
- 게이지마다 정의·상승 조건·하락 조건·1턴 변동폭이 명시된다. 이름만으로 오해할 여지가 있으면 정의를 직접 쓴다.
- 두 게이지의 역할이 겹치지 않는다.
- 등장인물 필드 Register Shift의 구간 이름과 변수 목록의 게이지 이름이 같다.
- 원본에 변수 정보가 없으면 템플릿 기본 변수(위치·스토리날짜·현재시각·최근사건·감정)를 쓴다. 다음일정은 일정·자동 이벤트가 서사를 미는 장르일 때만, 관계모드는 성별 분기가 있을 때만, 들킨_비밀은 설명 필드에 Secrets 항목이 있을 때만 둔다. 장르·인물에 맞지 않는 기본 변수는 채우지 않고 칸을 비워 둔다.
- 게이지 시작값·구간 행동은 등장인물·설명 필드의 설정에서 끌어낸다. 원본에 없는 새 설정을 만들지 않는다.
- 진행 관리용 변수(관계모드·들킨_비밀)는 상태창 표시 대상이 아님을 전제로 작성한다.

### 로어북
- 응답 시 위에서부터 합산 3,000자까지만 적용된다. 동시 호출될 수 있는 최악 조합이 3,000자 이내다.
- 상시 발동 항목을 두지 않는다. 세계관·상시 설정은 설명 필드로 간다.
- 트리거 키워드가 너무 흔한 단어가 아니다.
- 설명 필드와 로어북에 같은 내용이 중복되지 않는다.
- 명령어 출력은 유저 전용 메타 기능이며, 작중 인물이 인지하지 않고, 본편에 없는 큰 사건을 만들지 않고, 시간·변수가 멈춘다.
- 자동 이벤트에 필요한 정보는 로어북에만 두지 않는다.
- 필수 3종(!요약·!일기·!속마음)을 포함하고, 명령어는 9개 내외로 역할이 겹치지 않는다. (회고형 / 실시간형 / 외부 시선 / 수집물)
- 오락 명령어는 캐릭터의 직업·소속·세계관·성격에서 끌어낸다. 제3자 시선 창구가 최소 1개 있다.
- 출력 형식: 게시판·문서를 흉내 내는 것은 코드블록(구분선 12자 이내), 사람이 쓰고 읽는 글은 마크다운.
- 캐릭터 설정 항목의 트리거는 그 항목이 실제로 화제가 될 때만 걸리게 좁힌다.

## 캐릭터 설계 원칙
- 수동적 행동(기다림·갈망)만으로 구성된 캐릭터가 아니다. 먼저 움직이는 행동이 있다.
- 자동 이벤트는 명령어에 의존하지 않고 {{user}} 입력 없이 발생한다.
- 지향성·성향은 라벨 대신 행동으로 기술된다.
- 모티브 작품을 쓰면 적용 층위(겉 / 기저)가 명시된다.
- {{user}} 전제는 고정 전제와 기본값(페르소나 우선)으로 나뉜다.
- 성별 분기는 판정 규칙 한 번 + 각 모드의 차이점만 기술된다.
- 젠더 분류는 여성/남성/중립. '미정'이나 '비여성' 같은 부정형 분류 X
- 비밀(Secrets)은 숨긴 사실이 들키는 것 자체가 관계를 움직이는 캐릭터에만 둔다. 일상물·러브코미디처럼 관계가 깊어지며 드러나는 성격·과거는 비밀이 아니라 Facet·심층으로 쓰고 추적 변수를 두지 않는다. 장르·인물을 보지 않고 비밀 항목을 기본으로 넣지 않는다.
- 비밀 항목이 있으면 폭로 후 행동 변화(After Reveal)가 함께 있다.
- 같은 설정이 두 곳에서 다르게 기술되지 않는다.

## 판정 기준
- 금지/필수 규칙의 약화·강화, 핵심 설정의 누락, 명백한 환각 → 실패
- 변수·로어북의 {{user}} 표기, 변수 200자 초과, 변수 이름 공백 → 실패
- 세이프티 락·상태창 출력 지시 포함 → 실패
- 게이지 구간 누락, 문서 간 설정 충돌, 관계 모드에서 성립하지 않는 문장 → 실패
- 프롬프트 전체 30,000자 초과 → 실패 / 20,000자 초과 → 경고
- 로어북 필수 3종 누락 → 실패
- 로어북 최악 조합 3,000자 초과 가능성, 중복 기술, 흔한 트리거 키워드 → 경고
- 플랫폼 문체지침과의 경미한 충돌, 수동적 행동 비중 과다 → 경고
- 표현만 조금 달라졌거나 판단이 애매한 경우 → 경고
